## 2. الوصف العام

### 2.1 رؤية المنتج
- **المشكلة:** فوضى المجلدات وصعوبة الوصول الفوري لمعلومات المشاريع (اشتراكات، منصات، بريد، متغيرات) — وقت مهدور وممل.
- **الحل:** مساحة عمل هرمية واحدة (تبويب → فرع → قسم → مشروع) ببطاقة "حياة المشروع" الكاملة + تنبيهات تجديد + بحث بنيوي بالفلاتر.
- **التميّز التنافسي:** لا منافس يوفر سجل الاشتراكات/المنصات/البريد المسجل لكل مشروع + مساعد "البدء من أي نقطة" + الفلاتر المنسدلة بخيار "جديد".

### 2.2 بيئة التشغيل
- أندرويد (مقترح تقني: API 26+ / Android 8.0 وما فوق — يغطي الغالبية العظمى من الأجهزة).
- التشغيل محلي 100% للبيانات؛ الاتصال مطلوب فقط للمصادقة (Firebase) وللتحقق من الشراء (Play Billing) — وكلاهما بنية Google لا نديرها.

### 2.3 القيود
- الالتزام الكامل بسياسات Google Play (القسم 8-9).
- صفر تكاليف سيرفرات: لا خادم خاص للمشروع.
- قاعدة العمل الملزمة حتى هذه اللحظة: لا كتابة كود قبل أمر المالك (D-001).
- بيئة البناء معتمدة (D-019): التطوير يبدأ في بيئة العمل الحالية للمطوّر، مع إمكانية الانتقال إلى أي بيئة يطلبها المطوّر عند الحاجة.

### 2.4 الافتراضات والاعتماديات
- توفر خدمات Firebase وPlay Billing في أسواق الاستهداف.
- ملكية حساب Google Play Developer (25$ مرة واحدة — قرار المالك عند بدء النشر).

## 3. المتطلبات الوظيفية (نهائية)

### FR-01 — الدخول والتسجيل (D-005، D-006)
| السلوك | التفصيل |
|--------|---------|
| تسجيل بالبريد | بريد + كلمة مرور (8+ أحرف مع قياس القوة) + تأكيد |
| تسجيل بجوجل | نقرة واحدة عبر Credential Manager، ربط تلقائي بحساب بريدي موجود بنفس البريد |
| الدخول | بقاء الجلسة + خروج يدوي |
| نسيت كلمة المرور | رابط إعادة ضبط آمن للبريد (صالح 60 دقيقة) — لا إرسال كلمة مرور نصاً |
| رسائل الخطأ | واضحة وآمنة (لا كشف إن كان البريد مسجلاً في إعادة الضبط) |

### FR-02 — لوحة إعدادات المالك (D-008، Q3)
| السلوك | التفصيل |
|--------|---------|
| كلمة المرور | تغيير بتأكيد الحالية + الجديدة مرتين |
| الثيمات | 8 قوالب بنمط وحيد (4 فاتحة، 4 داكنة) — تطبيق فوري وحفظ |
| العنوان الرئيسي | نص حر حتى 60 حرفاً في رأس الصفحة الرئيسية |
| تصدير/استيراد | JSON مضغوط — استيراد بمعاينة واستراتيجية (استبدال/دمج) |
| مجلد يدوي | عبر SAF للتصدير/الاستيراد فقط — القاعدة تبقى داخل المساحة الخاصة |

### FR-03 — البنية الهرمية (D-007، D-010)
| السلوك | التفصيل |
|--------|---------|
| التسلسل | تبويب رئيسي → فرعي → أقسام → مشاريع (4 مستويات) |
| القوالب | 4 قوالب معتمدة (زبون/شخصي/اشتراك/ملاحظة) + مخصص بلا قالب |
| المساعد | زر إنشاء → اختيار النوع → قوائم منسدلة متسلسلة للأب مع خيار "جديد" في كل مستوى |
| التعديل/الحذف | تعديل أي حقل في أي مستوى؛ حذف بتأكيد وتحذير تسلسلي |
| 🗑️ سلة المحذوفات + التراجع الفوري | **ضمن MVP** (D-010) — شريط SnackBar "تراجع" بعد كل حذف + سلة بمدة استرجاع |

### FR-04 — البحث والفلترة
- قوائم منسدلة (تبويب/فرع/قسم/نوع/حالة) محتواها من الموجود فعلياً + خيار "➕ جديد" أعلى كل قائمة.
- نتائج فورية تتحدث مع كل اختيار + بحث نصي حرفي.

### FR-05 — الواجهة الرئيسية
- العنوان المخصص + شبكة التبويبات (أيقونة + اسم + عدد المشاريع) + قسم "الأكثر زيارة" (عدّاد فتح آخر 7 أيام) + زر إنشاء عائم + آخر ما فُتح.

### FR-06 — عناصر العقدة (D-007)
| العنصر | التفصيل |
|--------|---------|
| روابط | عنوان + URL + تصنيف (مستودع/لوحة/موقع/متجر/أخرى) |
| ملاحظات | حتى 50 لكل عقدة، بترتيب زمني وتنقّل، عنوان اختياري + محتوى |
| تنبيهات | تاريخ/وقت + تذكير مسبق — إشعارات نظام تعمل والتطبيق مغلق |

## 8. المتجر والنشر (D-013)

- **Google Play حصرياً للإطلاق الأول** — حساب ناشر 25$ مرة واحدة + حساب تاجر Payments.
- مسار النشر: Internal Testing → Open Beta → Production.
- الأصول المطلوبة: أيقونة 512px، لقطات شاشة، وصف عربي/إنجليزي، سياسة خصوصية (رابط عام)، نموذج Data Safety، تصنيف محتوى، App Bundle موقّع بـ Target SDK حديث.

## 9. الخصوصية والامتثال (D-016)

- سياسة خصوصية ثنائية اللغة على رابط عام (البريد + معرف الجهاز فقط — لا محتوى).
- زر "حذف حسابي" داخل التطبيق (حذف بيانات Firebase فوراً — إلزامي في Play).
- امتثال GDPR/CCPA بالحد الأدنى المطلوب لتطبيق ببيانات محلية.
- شاشة موافقة تحليلات عند أول تشغيل (D-017).
