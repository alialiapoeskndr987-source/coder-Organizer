# المحور A — تحليل السوق والمنافسين (مختصر)

## فئات المنافسين على Google Play

| الفئة | أمثلة | نقاط قوتها | نقطة ضعفها أمام فكرتنا |
|-------|-------|------------|--------------------------|
| 1. مساحات العمل العامة | Notion، AppFlowy، Obsidian | مرونة بلا حدود، مجتمع كبير | معقدة للمبتدئ، لا سجل اشتراكات/منصات/بريد جاهز |
| 2. منظمو المهام | Todoist، TickTick، Super Productivity | سرعة، تنبيهات ممتازة | مهام فقط — لا بنية مشاريع بتفاصيلها |
| 3. أدوات المستقلين للفوترة والوقت | Hourly trackers، Bonsai-style | تتبع وقت وأموال | لا تنظم معلومات المشروع التقنية نفسها |
| 4. مديرو كلمات المرور | Bitwarden، KeePass | أمان بيانات الدخول | سياق واحد مسطح — لا تنظيم مشاريع ولا تنبيهات تجديد |
| 5. تطبيقات الملاحظات | Joplin، Keep | بسيطة وخفيفة | فوضى مع كثرة المشاريع — بلا فلاتر بنيوية |

## فجوة السوق (فرصتنا)

- **لا يوجد تطبيق واحد** يجمع: شجرة هرمية + سجل اشتراكات/منصات/بريد/متغيرات لكل مشروع + تنبيهات تجديد + بحث بفلاتر بنيوية.
- الجمهور المستهدف الأولي (مبرمجون ومستقلون) يعاني من مشكلة موثقة وحقيقية — وهي مشكلة **المستخدم نفسه** (Dogfooding: نبني لنا).
- ميزات تنافسية لم تُشبَع: مساعد "البدء من أي نقطة"، الفلاتر المنسدلة بخيار "جديد"، بطاقة "حياة المشروع" الكاملة.

## التسعير السائد في الفئة

| النموذج | السائد | ملاءمتنا |
|---------|--------|----------|
| Freemium + اشتراك شهري/سنوي (2-5$/شهر) | الأكثر شيوعاً | خيار مطروح |
| شراء واحد (5-15$) | شائع في أدوات الإنتاجية | مناسب لجمهور المبرمجين |
| مجاني بإعلانات | شائع لكنه يضر السمعة عند المبرمجين | غير موصى به |

> **قرار التسعير مؤجل** — يُناقش تفصيلاً في المحور 6 كما هو معتمد في خارطة الطريق.

# المحور B — الميزات الوظيفية التفصيلية

## تفكيك FR-01 — الدخول والتسجيل

| السلوك | التفصيل |
|--------|---------|
| تسجيل بالبريد | بريد + كلمة مرور (8+ أحرف، تحقق قوة) + تأكيد كلمة المرور + التحقق من صيغة البريد + رسالة تحقق بريدي اختيارية |
| تسجيل بجوجل | زر Google بنقرة واحدة (Credential Manager)، يستخرج البريد والاسم تلقائياً، يربط الحساب بنفس البريد الموجود مسبقاً إن وجد (منع التكرار) |
| دخول بالبريد | تذكر الجلسة (بقاء مسجل الدخول)، خروج يدوي |
| نسيت كلمة المرور | إدخال البريد → رسالة نجاح عامة (لا نكشف إن كان البريد مسجلاً — أمان) → رابط صالح 60 دقيقة → صفحة ضبط جديدة |
| حالات الخطأ | رسائل واضحة: بريد مستخدم مسبقاً، كلمة مرور خاطئة، لا اتصال |

## تفكيك FR-02 — لوحة إعدادات المالك

| السلوك | التفصيل |
|--------|---------|
| تغيير كلمة المرور | يتطلب كلمة المرور الحالية + الجديدة مرتين + إلغاء الجلسات الأخرى اختيارياً |
| الثيمات | 8 قوالب جاهزة (انظر المحور C) + تطبيق فوري بلا إعادة تشغيل + حفظ الاختيار |
| العنوان الرئيسي | نص حر حتى 60 حرفاً يظهر أعلى الصفحة الرئيسية + خط ولون من الثيم |
| تصدير البيانات | ملف JSON مضغوط (يحوي البنية الكاملة + الملاحظات + الروابط) — يُحفظ في مجلد المستخدم أو التنزيلات |
| استيراد البيانات | اختيار ملف → معاينة موجز (عدد العناصر) → استراتيجية الدمج: استبدال كامل أو دمج مع تجاهل المكرر |
| مجلد التخزين اليدوي | عبر SAF: المستخدم يختار مجلداً من نافذة النظام ويمنح إذناً دائماً — يُستخدم لملفات التصدير/الاستيراد (قاعدة البيانات تبقى داخل التطبيق لأمانها) |

## تفكيك FR-03 — البنية الهرمية

| السلوك | التفصيل |
|--------|---------|
| الإنشاء الهرمي | تبويب رئيسي → تبويب فرعي → قسم → مشروع، بحد أقصى معلن للمستويات الأربعة المعتمدة |
| القوالب | عند إنشاء أي عقدة: قائمة قوالب مقترحة + "مخصص بلا قالب" |
| التعديل | تعديل الاسم/الحقول/الترتيب في أي مستوى في أي وقت |
| الحذف | تأكيد + تحذير واضح بالحذف التسلسلي للمحتويات + (Q9: سلة محذوفات؟) |
| مساعد البدء من أي نقطة | زر "إنشاء" → سؤال النوع (تبويب/فرع/قسم/مشروع) → قوائم منسدلة متسلسلة للأب: اختيار موجود أو "➕ جديد" → فتح نموذج القالب |
| الترتيب | سحب وإفلات داخل نفس المستوى + فرز تلقائي اختياري (أبجدي/أحدث) |

## هيكل الشاشات (9 شاشات أساسية)

1. **البداية (Splash)** — شعار + تهيئة
2. **الدخول/التسجيل** — تبويبان + زر جوجل + نسيت كلمة المرور
3. **الرئيسية** — العنوان المخصص + شبكة التبويبات + الأكثر زيارة + زر إنشاء عائم
4. **متصفح الشجرة** — تنقل تنازلي مع مسار تفصيلي (Breadcrumb) وقوائم
5. **تفاصيل العقدة (المشروع)** — بطاقة تعريف + روابط + ملاحظات (تنقّل حتى 50) + اشتراكات + منصات + تنبيهات
6. **مساعد الإنشاء** — قوائم منسدلة متسلسلة (النوع → الأب مع "جديد") → نموذج القالب
7. **البحث والفلترة** — فلاتر منسدلة + نتائج فورية
8. **الإعدادات** — كلمة المرور/الثيمات/العنوان/تصدير-استيراد/مجلد التخزين
9. **مركز التنبيهات** — التجديدات والتذكيرات القادمة مرتبة زمنياً

## تدفق الاستخدام الأساسي (سيناريو الذهب)

فتح التطبيق → رئيسية → زر إنشاء (عائم) → "مشروع" → منسدلة التبويب (يختار موجوداً أو جديد) → منسدلة الفرع → منسدلة القسم → اختيار قالب "مشروع لزبون" → تعبئة الاسم والزبون → حفظ → تفتح تفاصيل المشروع → يضيف رابط المستودع وملاحظة وتنبيه تجديد الدومين → يعود للرئيسية (ظهر المشروع في الأكثر زيارة).

# المحور D — الجوانب التقنية (البنية المختلطة)

## المبدأ المعتمد: محلي أولاً + مصادقة سحابية

| الطبقة | التقنية المقترحة | الدور |
|--------|------------------|-------|
| الواجهات | Flutter (قرار D-004) | كود واحد لأندرويد لاحقاً iOS إذا توسعنا |
| إدارة الحالة | Riverpod | معمارية نظيفة قابلة للاختبار |
| قاعدة البيانات | SQLite عبر Drift | **مصدر الحقيقة المحلي** — تعمل بلا إنترنت كلياً |
| المصادقة | Firebase Auth | جوجل + بريد/كلمة + رسائل إعادة الضبط (قرارا D-005 وD-006) |
| الإشعارات | flutter_local_notifications + WorkManager | تنبيهات دقيقة حتى مع إغلاق التطبيق |
| التخزين اليدوي | SAF (Storage Access Framework) | اختيار مجلد المستخدم للتصدير/الاستيراد فقط |
| التصدير | JSON مضغوط (Zip) | نقل كامل أو جهاز آخر بلا اعتماد على سحابة |
| المزامنة السحابية | Firestore — **مرحلة لاحقة اختيارية** | مزامنة بين الأجهزة لمن يريد (فصل تام عن النواة المحلية) |

## لماذا هذا المزيج؟

- **البيانات المحلية محمية:** قاعدة البيانات داخل مساحة التطبيق الخاص (غير مقروءة من تطبيقات أخرى)، وSAF يُستخدم فقط للنسخ الاحتياطي الذي يختاره المستخدم — يوازن بين قرار المستخدم "مجلد يدوي" وسلامة البيانات.
- **Firebase للمصادقة فقط** يعني: لا خادم نديره، تكلفة تشغيل شبه صفرية، وإمكانية عمل التطبيق 100% دون إنترنت بعد الدخول الأول.
- **مسار التوسع مفتوح:** إضافة المزامنة لاحقاً لا تعيد كتابة النواة لأن مصدر الحقيقة محلي منظّم.

## متطلبات متجر Google Play المرتبطة بهذه البنية

- سياسة خصوصية (تُذكر جوجل وFirebase) — يُعدّ محتواها في المحور 8.
- أذونات معلنة: إشعارات، (اختياري: الوصول عبر SAF لا يحتاج إذناً حساساً).
- Target SDK حديث + توقيع App Bundle (AAB).
